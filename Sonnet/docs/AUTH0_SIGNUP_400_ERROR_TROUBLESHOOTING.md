# Troubleshooting Auth0 Signup 400 Error

## Issue
Getting `POST https://dev-XXX.us.auth0.com/u/signup?state=... 400 (Bad Request)` error when trying to sign up with email/password, even though:
- Email database connection is enabled
- Connection is enabled for the application
- "Try Connection" works in Auth0 Dashboard

## Possible Causes and Solutions

### 1. State Parameter Issue
The `state` parameter in the URL might be malformed or too long. Auth0 has limits on state parameter length.

**Check:**
- Open browser DevTools → Network tab
- Look at the actual POST request to `/u/signup`
- Check the `state` parameter value
- Verify it's not excessively long or malformed

**Solution:**
- The state parameter is automatically generated by `@auth0/nextjs-auth0`
- If it's too long, there might be too much data encoded in it
- Try clearing browser cookies/cache and trying again

### 2. Universal Login Screen Configuration
The Universal Login screen might have validation rules that are causing the 400 error.

**Check in Auth0 Dashboard:**
- Go to **Branding → Universal Login → Login**
- Check if there are any custom validation rules
- Look for any Actions that might be interfering with signup

**Things to verify:**
- "Disable Sign Ups" is OFF in the connection settings
- No Actions blocking signup in the Pre-Login or Post-Login flows
- Email verification settings aren't blocking signup

### 3. Password Policy Validation
The password might not meet Auth0's password policy requirements.

**Check in Auth0 Dashboard:**
- Go to **Authentication → Database → Username-Password-Authentication → Settings**
- Check the **Password Policy** section
- Note the minimum requirements (length, complexity, etc.)

**Test:**
- Try a stronger password (8+ characters, mix of letters/numbers, special characters)
- Or temporarily relax the password policy for testing

### 4. Email Format or Domain Restrictions
There might be email domain restrictions or format validation issues.

**Check in Auth0 Dashboard:**
- Go to **Authentication → Database → Username-Password-Authentication → Settings**
- Look for "Blocked Email Domains" or similar restrictions
- Check if Hotmail/Outlook domains are blocked

**Test:**
- Try signing up with a Gmail address to see if it's domain-specific
- Check Auth0 Logs (Monitoring → Logs) for specific error messages

### 5. Connection Name Mismatch
If you're using a custom connection name, it must match what's configured.

**Check:**
- Default connection name should be: `Username-Password-Authentication`
- If you created a custom connection, verify the name is correct

### 6. Application Settings - OIDC Conformant Mode
Check if OIDC Conformant mode settings are causing issues.

**Check in Auth0 Dashboard:**
- Go to **Applications → Your App → Settings**
- Under **Advanced Settings → OAuth**
- Check "OIDC Conformant" setting
- Should typically be ON for modern Auth0 apps

### 7. Check Auth0 Logs for Detailed Error
The 400 error from Auth0 should have more details in the Auth0 logs.

**Steps:**
1. Go to Auth0 Dashboard → **Monitoring → Logs**
2. Try signing up again
3. Immediately check the logs for the most recent entry
4. Look for the actual error message (it will be more specific than just "400")

**Common log errors:**
- `password is too weak` - Password policy issue
- `email already exists` - User already signed up
- `invalid email format` - Email validation issue
- `connection not enabled` - Application not enabled for connection
- `state parameter invalid` - State parameter issue

### 8. Browser/Network Issues
Sometimes the issue is with how the browser is sending the request.

**Try:**
- Clear browser cache and cookies
- Try in an incognito/private window
- Try a different browser
- Check browser console for JavaScript errors

### 9. Next.js Auth0 SDK Configuration
Check if there are any issues with how `@auth0/nextjs-auth0` is configured.

**Check environment variables:**
- `AUTH0_SECRET` - Should be set (required by Auth0 SDK)
- `AUTH0_BASE_URL` - Should match your frontend URL
- `AUTH0_ISSUER_BASE_URL` - Should be `https://your-tenant.us.auth0.com`
- `AUTH0_CLIENT_ID` - Your Auth0 application client ID
- `AUTH0_CLIENT_SECRET` - Your Auth0 application client secret

**Verify in `periodictabletop/.env.local` or Vercel environment variables**

### 10. Universal Login Version
Check which version of Universal Login you're using.

**In Auth0 Dashboard:**
- Go to **Branding → Universal Login**
- Check if you're using "Classic" or "New" Universal Login experience
- Try switching to see if it resolves the issue
- "New" Universal Login is recommended

## Debugging Steps

1. **Enable Detailed Logging:**
   - In Auth0 Dashboard → Applications → Your App → Settings
   - Enable "Enable Debug Logs" (if available)
   - Check Monitoring → Logs after attempting signup

2. **Check Browser Network Tab:**
   - Open DevTools → Network
   - Filter for "signup" or "auth0"
   - Click on the failed request
   - Check:
     - Request URL (full URL with all parameters)
     - Request Headers
     - Request Payload/Body (if POST)
     - Response (should show the actual error message)

3. **Check Browser Console:**
   - Look for JavaScript errors
   - Look for any Auth0 SDK errors
   - Check for CORS errors

4. **Test Direct Auth0 Login URL:**
   - Try going directly to: `https://your-tenant.us.auth0.com/u/login?client=YOUR_CLIENT_ID`
   - See if signup works there
   - This helps isolate if it's a frontend issue or Auth0 configuration issue

## Most Likely Fix

Given that "Try Connection" works, the most likely issues are:

1. **Password Policy** - Try a stronger password (12+ chars, mix of upper/lower/numbers/special)
2. **Email Domain Blocking** - Check if Hotmail is blocked (unlikely but possible)
3. **Auth0 Logs** - Check Monitoring → Logs for the actual error message
4. **State Parameter** - Might be too long or malformed (less likely but possible)

## Quick Test

Try this to get more information:

1. Open browser DevTools (F12)
2. Go to Network tab
3. Try signing up
4. Find the failed POST request to `/u/signup`
5. Click on it and check:
   - **Headers** tab → Request Payload (see what data is being sent)
   - **Response** tab → See the actual error message from Auth0
   - **Preview** tab → Sometimes shows formatted error

The response should contain a more specific error message than just "400 Bad Request".
